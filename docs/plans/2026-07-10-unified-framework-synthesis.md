## 1. Executive summary

Thought Tube / Inner World is not three products and not three ontologies. It is **one meaning operating system** with:

| Layer | What it is | Source frameworks |
|-------|------------|-------------------|
| **Ontology** | How meaning exists | ThoughtShape grammar on MTSF substrate |
| **Dynamics** | How meaning moves | SDS overlay (on demand) |
| **Persistence** | How meaning is stored | MTSF kernel (operational) |
| **Capture** | How meaning enters | Reasoning-step + Hold semantics |
| **Curation** | How meaning shapes inner life | Inner Space Curator surface |
| **Network** | How meaning connects people | Community pipeline + reasoning clustering |

**Core claim:**

> A thought is a dynamic, multidimensional meaning-shape. People lose thoughts when capture asks for the wrong granularity at the wrong time. The product must hold ambiguity, trace reasoning, curate inner space, and eventually cluster people by how they think — not just what they think about.

**Build discipline:**

1. Finalize this synthesis and unified ontology
2. Extend schemas / contracts to match
3. Build surfaces and pipeline around the kernel
4. Do not implement parallel ontologies

## 2. Conversation arc (what was decided)

### 2.1 Three frameworks compared

Three frameworks were evaluated: **MTSF**, **SDS**, **ThoughtShape**.

Conclusion: they are **overlapping, largely concurring ontologies** — not competitors. They are three perspectives on one reality:

- **ThoughtShape** — phenomenological grammar (what meaning *is*)
- **MTSF** — persistence and discovery (what the system *remembers*)
- **SDS** — motion and intervention (what the system *infers about change*)

Full comparison: [THREE_FRAMEWORK_COMPARATIVE_EVALUATION.md](../frameworks/THREE_FRAMEWORK_COMPARATIVE_EVALUATION.md)

### 2.2 Ontology concurrence confirmed

All three agree:

- thought is not a sentence
- meaning is relational, not atomistic
- pre-explicit field must be held without flattening
- context / lens / frame changes extraction
- provenance and confidence are mandatory
- progressive depth — do not over-structure early
- cross-domain insight is structural, not keyword-based

Differences are **emphasis**, not contradiction.

### 2.3 Step-by-step capture tool

**Problem:** Users lose thoughts when forced to drop too much detail too early, or when structure only appears at session close.

**Solution:** A **reasoning-step** capture instrument:

```text
Drop → Hold → Trace → Mirror → Prompt → Repeat
```

- **ReasoningStep** is the atomic unit (not session, not finished formation)
- Each step links via `prompted_by` + `move_type` (extends, grounds, contrasts, bridges, revises…)
- Structure deepens only when the user's reasoning arc supports it
- Questions tuned to **reasoning move**, not ontology vocabulary

### 2.4 Inner Space Curator (alternate surface)

**Alternate framing:** Not forensic replay — **inner space curation**.

> You are the content you consume. Curate your own world.

- Inner world as **mirror shaping reality**, not filing cabinet
- Verbs: **place, tend, revisit, release, compose**
- Recognition → resonance → revisitation as deliberate practice
- Alchemical transformation chain maps to capture pipeline (see §5)

Same kernel. Different ritual shell from Thought Trace.

### 2.5 Community pipeline (growth flywheel)

**Vision:** Social → waitlist → reasoning-calibrated intake → product → clustering → community → founder feedback loop.

Key mechanism:

- Chatbot **mimics user's reasoning** in questioning (not generic Q&A)
- Extract **reasoning signature** per user (Pilot 003 model)
- **Cluster** by reasoning topology, not demographics
- **Mutate product per cluster** — different shells, same kernel
- Connect people through **compatible reasoning moves**

This is the network layer — where compounding happens.

## 3. Unified ontology (final framework)

One canonical object model. Three views. Optional overlays.

### 3.1 Core formula

```text
Station × Dimension × Facet = StateClaim
ThoughtShape = relations between StateClaims across dimensions
```

Compressed pipeline:

```text
Field → Entity → Dimension → Frame → Station → Facet/Subsystem
     → StateClaim → Relation → Event → Expression → Update
```

Operational runtime:

```text
Capture → Hold → Differentiate → Shape → Locate → Compare
       → Transform → Express → Evaluate → Update
```

### 3.2 Primitive definitions

| Primitive | Definition |
|-----------|------------|
| **Field** | Pre-clear possibility; meaningful but not yet resolved |
| **Entity** | Carrier of meaning (person, brand, idea, product, self) |
| **Dimension** | Layer of interpretation (psychological, brand, financial, narrative…) |
| **Frame** | Interpretive stance / lens active now |
| **Station** | Possibility-space where a kind of meaning can vary (recognition, safety, clarity…) |
| **Facet** | Specific aspect within station × dimension (logo recognition ≠ meaning recognition) |
| **Subsystem** | Facet expanded when reasoning requires depth |
| **StateClaim** | Qualified condition with evidence, confidence, weight, salience, valence |
| **Relation** | Directional influence within or across dimensions |
| **Event** | State change, disclosure, transformation (Tajallī) |
| **Tension** | Unresolved pressure inside the shape |
| **Expression** | External surface (sentence, scene, spec, ritual, UI…) |
| **Provenance** | Source of structural knowledge (confirmed / inferred / hypothetical / contradicted) |
| **Formation** | Stabilized whole emerging from multiple steps / state-claims |
| **Shape** | Relation topology across state-claims |
| **Stencil** | Abstract pattern of shape (cross-domain match key) |
| **ReasoningStep** | Atomic capture unit with move type and trace links |
| **ReasoningSignature** | Recurring move sequence for a person |
| **MovementSignature** | SDS overlay: system in motion, loops, archetype |

### 3.3 Maqām → Ḥāl → Tajallī (philosophical root)

| Arabic | Unified term | Role |
|--------|--------------|------|
| Maqām | Station | Space where meaning can vary |
| Ḥāl | StateClaim | Current actualization |
| Tajallī | Event | Disclosure / transformation |

### 3.4 Three views on one object

```text
                    ┌─────────────────────────────┐
                    │   Unified ThoughtObject      │
                    │   (MTSF-backed store)        │
                    └──────────────┬──────────────┘
                                   │
         ┌─────────────────────────┼─────────────────────────┐
         │                         │                         │
  ThoughtShape view           MTSF view                SDS view (optional)
  dimensions, facets,         entities, shapes,         loops, archetypes,
  lenses, tensions            stencils, discovery       analogies, intervention
```

Do not build three stores. Build one store with three projections.

### 3.5 Invariants (do not violate)

1. **Save before interpret** — T0 append on every drop
2. **Hold is valid** — ambiguity is not failed extraction
3. **Progressive depth** — facet → subsystem only when earned
4. **Provenance everywhere** — no hallucinated inner world
5. **Silence / contradiction may remain**
6. **Lens is access mode**, not a free-form prompt
7. **Reasoning trace is editable** — user can correct move links
8. **One ontology** — no parallel entity registries per framework

## 6. Reasoning signature and clustering

### 6.1 Per-user reasoning signature

Prototype: Pilot 003 `stress-tested systems builder`

```text
ground mechanism → triangulate → demand concretion → escalate abstraction
→ bridge product → formalize shape → symmetry → inversion → seek canon
```

Stored fields:

- `dominant_moves[]`
- `epistemic_stance`
- `preferred_abstraction_register[]`
- `recurring_tensions[]`
- `stability` (provisional → emerging → stable)
- `provenance` (which sessions contributed)

### 6.2 Mimic-reasoning questioning

The bot copies **interrogation style**, not content:

| User move pattern | Ask | Do not ask |
|-------------------|-----|------------|
| Grounding-first | "What concrete instance?" | "What's the framework?" |
| Triangulating | "More like A or B?" | "Define your terms" |
| Bridge-building | "How does this connect outward?" | "Stay theoretical" |
| Formalizing | "What's the shape here?" | "How does it feel?" |
| Canon-seeking | "What would make this reusable?" | "Keep exploring" |

Extends Personal Interface calibration from **communication style** to **reasoning moves**.

### 6.3 Cluster model

Clusters are **reasoning topologies**, not demographics:

```text
Cluster A: mechanism → triangulate → formalize     (builders)
Cluster B: felt-sense → metaphor → narrative       (curators)
Cluster C: contrast → inversion → counterpattern   (critics)
Cluster D: resonance → aesthetic → taste law       (tastemakers)
```

Each cluster gets:

- onboarding shell (Trace vs Curator emphasis)
- mimic-bot tuning
- social content lane
- product mutation target

### 6.4 People ↔ people matching

Match on **compatible reasoning moves**, not shared topics:

- bridge-builders ↔ formalizers (translate inner → outer)
- inverters ↔ symmetrists (mutual stress-test)
- resonators ↔ narrators (atmosphere + story)

## 7. Community pipeline (end-to-end)

```text
1. ATTENTION       Social: mirror, curation, inner space, taste
2. WAITLIST        Reasoning intake (not email-only form)
3. CALIBRATION     Mimic-bot: 5–10 turns → provisional signature
4. ONBOARDING      First drops / first mirror placement
5. CLUSTER         Signature → cluster → community lane
6. PRODUCT         Cluster-specific shell on shared kernel
7. FEEDBACK        Founder dashboard: cluster signal → product tweak
8. CONNECTION      Reasoning-compatible intros (later)
```

### 7.1 Waitlist bot flow

```text
1. "Say something you're trying to figure out."
2. Infer first reasoning move
3. Ask next move in THEIR arc
4. After 5–8 turns → provisional signature
5. Assign cluster + lane
6. Invite to early product access
```

### 7.2 Founder feedback loop

Observe per cluster:

- dominant moves and where mimic fails
- resonance / rejection patterns
- which shell converts
- what questions unlock depth

Mutate product **per cluster**, not globally.
