# Three-Framework Comparative Evaluation

**MTSF · SDS · ThoughtShape**

**Date:** 2026-07-08  
**Purpose:** Compare three frameworks developed for Thought Tube and recommend how they compose.

---

## 1. Executive Summary

Three frameworks address different layers of the same problem: how to represent thought beyond flat text, and how to make that representation useful for reasoning, memory, and product surfaces.

| Framework | Core unit | Primary question | Status |
|-----------|-----------|------------------|--------|
| **MTSF** (Metaphysical Thought-Space Framework) | Shape / stencil on entities + qualities + relations | What exists in mind-space, and how does it become artifact? | **Operational** — kernel implemented, 13/13 gap evals, brainwalk corpus extracted |
| **SDS** (System-Dynamic Signature) | Movement signature / system in motion | What transformation is happening, and what cross-domain analogies hold? | **Design only** — v1.0 report, no code in repo |
| **ThoughtShape** | Multidimensional meaning-shape | What is the relational configuration of meaning across dimensions, and how do lenses access it? | **Design only** — chat-developed framework, no code in repo |

**Conclusion:** These are not competitors. They are **stackable layers**:

```text
ThoughtShape  →  phenomenological grammar + lens routing (what meaning *is*)
MTSF          →  persistent substrate + discovery + actualization (what the system *stores*)
SDS           →  dynamic reasoning + analogy + intervention (what the system *does with motion*)
```

Thought Tube should treat **ThoughtShape as the user-facing ontology**, **MTSF as the storage and discovery kernel**, and **SDS as the cross-domain reasoning engine** that operates on extracted shapes when movement, failure, and intervention matter.

## 2. What Each Framework Optimizes For

### 2.1 MTSF — Persistent Mind Substrate

MTSF models pre-material thought as navigable structure across three spaces:

- **Metaphysical** — pre-formed possibility
- **Latent** — operational bridge (embeddings, transformers)
- **Actual** — artifacts and externalized outputs

Its pipeline:

```text
Field → Entity → Quality → Relation → Shape → Stencil → Artifact
```

MTSF optimizes for:

- **Durability** — what gets remembered across sessions
- **Discovery** — finding candidate shapes without pre-known templates
- **Actualization** — binding constraints to produce artifacts
- **Provenance** — evidence-backed assertions, quarantined analogical matches
- **Silence** — unresolved contradiction is valid output

**Strength:** A running kernel with schemas, seeds, evals, and extracted brainwalk corpus.  
**Weakness:** Flat entity/quality model; lenses and multidimensionality are thin; causal dynamics and intervention are secondary.

### 2.2 SDS — Cross-Domain Structural Reasoning

SDS treats input as a **system in motion**: entities with roles, states, causal relations, feedback loops, constraints, and failure modes. It extracts a **movement archetype** and matches it against a living library for analogy and intervention.

Its pipeline:

```text
Field → Entities+Roles → States → Causal Relations → Feedback Loops
     → Movement Archetype → Analogies → Transfer Ledger → Intervention
```

SDS optimizes for:

- **Transformation** — what is changing, not just what exists
- **Cross-domain transfer** — structural alignment, not semantic similarity
- **Anti-matches** — explicit rejection of false analogies
- **Observer lens** — extraction is constitutively framed
- **Constraints and absences** — blockages as first-class
- **User-validated memory** — living archetype library

**Strength:** Best framework for "same movement under different costumes" and intervention design.  
**Weakness:** No persistent mind substrate; no faceted multidimensional entity model; not yet implemented.

### 2.3 ThoughtShape — Multidimensional Meaning Grammar

ThoughtShape models thought as a **dynamic, multidimensional meaning-shape**. A thought is not a sentence; it is a relational configuration across entities, dimensions, stations, facets, state-claims, relations, and events.

Its pipeline:

```text
Field → Entity → Dimension → Frame → Station → Facet/Subsystem
     → StateClaim → Relation → Event → Expression → Update
```

Core formula:

```text
Station × Dimension × Facet = StateClaim
Thought-shape = relations between StateClaims across dimensions
```

Runtime operations:

```text
Capture → Hold → Differentiate → Shape → Locate → Compare
       → Transform → Express → Evaluate → Update
```

ThoughtShape optimizes for:

- **Multidimensionality** — same entity, many valid layers (brand, founder, financial, narrative…)
- **Faceted precision** — logo recognition ≠ meaning recognition
- **Progressive resolution** — facet stays simple until depth is needed
- **Lens routing** — Founder, Product, Risk, Financial, Story, Visual, Brand lenses as structured access modes
- **Tension and valence** — felt charge preserved, not flattened
- **Provenance and confidence** — anti-hallucination by design

**Strength:** Direct product fit for Thought Tube lenses; richest phenomenological model.  
**Weakness:** No implementation; no formal discovery pipeline; no explicit actualization bridge to artifacts.

## 3. Ontology Comparison

### 3.1 Core Unit

| Concept | MTSF | SDS | ThoughtShape |
|---------|------|-----|--------------|
| Atomic meaning carrier | Entity + QualityRegion | Entity + Role + State | Entity + Dimension + Station + Facet |
| Structured whole | Shape (configuration of qualities + relations) | System-Dynamic Signature | ThoughtShape |
| Abstract pattern | Stencil | Movement archetype | Cross-dimensional relation topology |
| Qualified claim | Assertion (evidence-backed) | State + evidence span | StateClaim (state, weight, salience, valence, confidence, evidence) |
| Pre-formed zone | ThoughtField | Pre-structured field / possibility cloud | Field |
| Change event | Temporal activation / actualization stage | State transition, feedback loop | Event / Tajallī |
| Unresolved pressure | Contradiction (may remain) | Failure mode, constraint | Tension |
| Interpretive frame | Activation context | Observer lens | Frame + Lens |
| Output surface | Artifact | Intervention pattern, analogy | Expression surface |

### 3.2 Relation to Maqām → Ḥāl → Tajallī

ThoughtShape's philosophical root maps cleanly onto all three frameworks:

| Arabic triad | ThoughtShape | MTSF | SDS |
|--------------|--------------|------|-----|
| Maqām (station) | Station — possibility-space where meaning varies | Quality type / role slot in stencil | State variable / role container |
| Ḥāl (state) | StateClaim — current actualization | Quality intensity / region state | State node value |
| Tajallī (disclosure) | Event — transformation or manifestation | Actualization stage / shape activation | State transition / loop firing |

ThoughtShape makes this triad **operational** by adding dimension, facet, and cross-dimensional relation — which MTSF and SDS only partially cover.

### 3.3 Multidimensionality

| | MTSF | SDS | ThoughtShape |
|---|------|-----|--------------|
| Same entity, multiple layers | Implicit via multiple shapes per entity | Implicit via role reassignment under lens | **Explicit** — Dimension as first-class layer |
| Station projects differently per layer | No | Partial (role remapping) | **Yes** — Station × Dimension → Projection |
| Facets within one station | No (qualities are flat regions) | No (states are typed but not faceted) | **Yes** — Station × Dimension × Facet → StateClaim |
| Cross-layer relations | Cross-register bridges (G03) | Feedback loops across roles | **Cross-dimensional relations** as core shape mechanism |

**Example — "People know the logo but don't get the brand":**

| Framework | Representation |
|-----------|----------------|
| MTSF | Entity: brand. Qualities: recognition (high), meaning (low). Relation: tension between familiarity and confusion. Candidate shape: surface-without-depth. |
| SDS | Entities: logo, brand meaning, user. States: high symbol recall, low semantic clarity. Causal chain: awareness ↑ without comprehension → conversion risk. Archetype: signal_without_semantics or dilution_through_accumulation. |
| ThoughtShape | Entity: Brand. Dimension: Brand. Station: Recognition. Facets: logo=high, meaning=low, category=confused. Tension: visual familiarity vs semantic instability. Cross-dimensional: weak meaning → positioning → conversion → founder confidence. |

ThoughtShape is the most **granular** representation. SDS adds **causal motion**. MTSF adds **persistence and discovery hooks**.

## 4. Pipeline Comparison

```text
                    MTSF                    SDS                 ThoughtShape
                    ────                    ───                 ────────────
Pre-structure       ThoughtField            Field               Field
Identify carriers   Entity                  Entity + Role       Entity
Layering            (implicit via shapes)     States              Dimension
Variation space     QualityRegion           State               Station
Precision           (flat qualities)        (typed states)      Facet / Subsystem
Qualified condition Quality + intensity     State + evidence    StateClaim
Topology            Relation (4-level)        Causal edge         Relation
Dynamics            Temporal activation     Feedback loop       Event
Pattern             Shape / Stencil         Movement archetype  Relation topology
Access mode         Activation context      Observer lens       Frame + Lens
Output              Artifact                Analogy/Intervention Expression
Feedback            Refined ThoughtField    User validation     Update
```

### 4.1 Progressive Depth

All three support some form of progressive resolution:

| Level | ThoughtShape | MTSF | SDS |
|-------|--------------|------|-----|
| 1 — Raw | Field: "something feels off" | Fast capture draft | Raw input |
| 2 — Basic | Entity → Station → unstable | Entity + sparse qualities | Entities + boundary |
| 3 — Layered | + Dimension | + candidate shape | + states + roles |
| 4 — Faceted | + Facets + StateClaims | + stencil projection | + causal relations |
| 5 — Deep | + Subsystem expansion | + deep extraction / embeddings | + feedback loops |
| 6 — Cross-domain | + cross-dimensional relations | + shape index match | + analogy + transfer ledger |

ThoughtShape names this principle most explicitly. MTSF implements it via fast/deep modes and facet completeness in the graph module. SDS implements it via abstraction levels before archetype matching.

### 4.2 Hold vs Over-Structure

| Framework | Anti-premature-structure mechanism |
|-----------|-------------------------------------|
| ThoughtShape | **Hold** — preserve ambiguity; meaningful but not yet clear |
| MTSF | Silence is valid; contradiction may remain unresolved |
| SDS | Missing information flagged; confidence scored on evidence coverage |

ThoughtShape's **Hold** step is the most product-facing articulation of a shared design value.

## 5. Lens and Access-Mode Comparison

This is where ThoughtShape is strongest and most directly product-relevant.

### 5.1 ThoughtShape Lenses

A lens is **not a prompt**. It is a structured access mode into a multidimensional ThoughtShape:

| Lens | Activates | Transforms into |
|------|-----------|-----------------|
| Founder | psychology, origin story, conviction, wound | manifesto, pitch, narrative |
| Product | user behavior, value clarity, onboarding | feature, UX fix, requirement |
| Risk | fragility, assumptions, failure paths | mitigation, tests |
| Financial | CAC, conversion, retention, pricing | unit-economics concern |
| Story | character, conflict, arc | scene, narrative structure |
| Visual | symbol, atmosphere, composition | moodboard, metaphor |
| Brand | recognition facets, trust, symbolism | positioning, messaging |

All lenses operate on the **same underlying ThoughtShape**.

### 5.2 SDS Observer Lens

SDS's `observer_lens` is constitutive of extraction: chef vs chemist vs systems_abstractor yields different entity foregrounding and causal structure. It shapes **how the signature is built**, not how it is transformed into output surfaces.

### 5.3 MTSF Activation Context

MTSF's shape activation (Module 14) uses `activation_context` to reduce identity and select which shape/stencil is live. This is closer to ThoughtShape lenses than SDS observer lens, but:

- MTSF has no predefined lens catalog
- MTSF does not specify per-lens dimension/station/facet activation
- MTSF does not define expression-surface routing

### 5.2 Lens Verdict

| Capability | MTSF | SDS | ThoughtShape |
|------------|------|-----|--------------|
| Lens affects extraction | Partial (activation context) | **Yes** (observer_lens) | **Yes** (frame) |
| Lens affects transformation | No | No (analogy is separate) | **Yes** (core design) |
| Lens catalog for Thought Tube | No | No | **Yes** (7 lenses defined) |
| Same object, multiple outputs | Via actualization | Via analogy transfer | **Via lens routing** |

**ThoughtShape should own the lens product model.** MTSF should store the shape that lenses read. SDS should supply cross-domain analogies when a lens needs "what does this pattern look like elsewhere?"

## 6. Cross-Domain Reasoning Comparison

### 6.1 The Shared Pattern

All three frameworks want to find:

```text
outer familiarity + inner misunderstanding
```

Across brand, relationships, religion, education, product, art.

| Framework | Mechanism | Example match surface |
|-----------|-----------|----------------------|
| MTSF | Stencil match + semantic adjacency in shape index | `surface-without-depth` stencil matches across sessions |
| SDS | Movement archetype + structural alignment + transfer ledger | `signal_dilution` archetype; anti-match if maze implies hidden path |
| ThoughtShape | Cross-dimensional relation topology + Compare operation | Recognition.brand.logo=high + Recognition.brand.meaning=low → retrieve similar tension shapes |

### 6.2 Comparative Strengths

| Dimension | Winner | Why |
|-----------|--------|-----|
| Prevent false analogies | **SDS** | Anti-matches, hybrid 5-layer evaluator, transfer ledger |
| Retrieve by shape not keyword | **ThoughtShape** | "Find high surface recognition + low deep understanding" |
| Discover unknown shapes | **MTSF** | Discovery pipeline, candidate shapes, no pre-known template required |
| Explain intervention | **SDS** | Intervention patterns from source domain |
| Preserve felt tension | **ThoughtShape** | Valence, tension, temporal contour as first-class |
| Session-to-session memory | **MTSF** | Assertion store, content graph, global graph |

### 6.3 Example — Brand Recognition Chain

Input: *"People recognize the logo very well, but the brand still feels unstable because they do not understand what it means."*

**ThoughtShape** structures the shape:

```text
Brand.Recognition.logo = high
Brand.Recognition.meaning = low
Brand.Recognition.category = confused
Tension: visual familiarity vs semantic instability
Cross-dim: meaning → positioning → conversion → instability
```

**SDS** structures the motion:

```text
Loop: awareness campaigns → logo recall ↑ → meaning unchanged → trust gap widens
Archetype: signal_without_semantics
Intervention: clarify lead signal before amplifying distribution
Anti-match: "maze" (implies hidden correct path; here there may be no path)
```

**MTSF** structures the substrate:

```text
Entity: brand (hub, 7/10 sessions)
Qualities: recognition, meaning, stability
Shape: cand-metaphysical-actual-bridge (field→landscape→probe→sink)
Stencil: surface-familiarity-without-semantic-depth
Persists to: global content graph, assertion store
```

All three are valid. They answer different questions about the same thought.

## 7. Data Model Mapping

A practical unified model can map concepts without forcing one framework to swallow the others:

```text
ThoughtShape (user/product layer)
├── Field              ← MTSF ThoughtField
├── Entity             ← MTSF Entity / SDS Entity
├── Dimension          ← (new; not in MTSF/SDS)
├── Station            ← MTSF QualityRole / ThoughtShape Station
├── Facet              ← (new; MTSF has facet completeness hooks in graph module)
├── StateClaim         ← MTSF Assertion / SDS State + evidence
├── Relation           ← MTSF Relation / SDS Causal edge
├── Event              ← SDS transition / MTSF temporal activation
├── Tension            ← MTSF contradiction / SDS failure mode
├── Shape              ← MTSF Shape / ThoughtShape relation topology
├── Stencil            ← MTSF Stencil / SDS Movement archetype (different abstraction level)
├── Lens               ← ThoughtShape Lens / SDS observer_lens
├── Expression         ← MTSF Artifact / ThoughtShape Expression surface
├── Provenance         ← all three
└── SDS overlay (optional per shape)
    ├── feedback_loops
    ├── constraints
    ├── movement_archetype
    ├── analogies
    ├── transfer_ledger
    └── anti_matches
```

### 7.1 Key Mapping Decisions

| ThoughtShape concept | MTSF home | SDS home | Notes |
|---------------------|-----------|----------|-------|
| Dimension | Extend entity schema | N/A | New layer; map to MTSF quality namespaces or tags initially |
| Station | QualityRole / stencil role slot | State container | ThoughtShape station is more phenomenological than SDS state |
| Facet | Sub-entity or quality subtype | N/A | MTSF graph already tracks facet completeness |
| StateClaim | Assertion store entry | State node + evidence span | Merge provenance models |
| Cross-dimensional relation | Cross-register bridge (G03) | Cross-role causal chain | ThoughtShape relation is not necessarily causal |
| Lens | Shape activation + new lens registry | observer_lens | ThoughtShape catalog is the product spec |
| Subsystem | Nested SubEntity (Module 05) | Recursive VSM nesting | Progressive resolution rule is shared |
| Compare | Shape index + semantic adjacency | Analogy generation layer | Different algorithms, same user intent |
| Evaluate | Shape utility evals (G11) | Hybrid evaluator | Merge rubrics |

## 11. Where They Overlap vs Complement

### 11.1 Overlap (do not build three times)

| Shared concern | Risk if duplicated | Single owner |
|----------------|-------------------|--------------|
| Field / pre-structure | Three capture pipelines | MTSF ingest + ThoughtShape Hold semantics |
| Provenance / confidence | Incompatible trust models | MTSF assertion store as canonical |
| Entity identification | Divergent entity registries | MTSF entity register |
| Relation storage | Split graphs | MTSF content graph as substrate; SDS edges as overlay |
| Cross-domain retrieval | Three indices | MTSF shape index + SDS archetype library as views |

### 11.2 Complement (stack, don't merge)

| MTSF provides | SDS provides | ThoughtShape provides |

| Stencil library | Movement archetype library | Station × Dimension × Facet ontology |
| Actualization bridge | Transfer ledger | Expression surface routing |

## 12. Recommended Architecture for Thought Tube

```text
┌─────────────────────────────────────────────────────────────────┐
│  PRODUCT LAYER — ThoughtShape                                   │
│  Lenses: Founder, Product, Risk, Financial, Story, Visual, Brand│
│  Runtime: Capture→Hold→…→Express→Evaluate→Update               │
│  UX: dimension-aware thought cards, facet drill-down, tension   │
├─────────────────────────────────────────────────────────────────┤
│  REASONING LAYER — SDS (on demand)                              │
│  Triggered when: analogy search, intervention design, failure   │
│  analysis, cross-domain compare                                 │
│  Outputs: movement archetype, analogies, anti-matches,          │
│           intervention patterns                                 │
├─────────────────────────────────────────────────────────────────┤
│  SUBSTRATE LAYER — MTSF (canonical store)                       │
│  ThoughtField, Entity, Quality, Relation, Shape, Stencil,       │
│  Assertion store, Content graph, Shape index, Discovery         │
└─────────────────────────────────────────────────────────────────┘
```

### 12.1 Integration Sequence

1. **Now — MTSF as store:** Continue extracting and persisting brainwalk corpus. MTSF remains source of truth.
2. **Next — ThoughtShape vocabulary in extraction:** Extend extraction skill to emit Dimension, Station, Facet, StateClaim alongside existing entity/quality/relation. Map to assertion store. No new storage system.
3. **Next — Lens registry:** Implement ThoughtShape's seven lenses as activation + expression profiles over MTSF shapes. Each lens declares: active dimensions, station filters, facet priorities, output surface types.
4. **Later — SDS overlay:** When user asks "what is this like in another domain?" or "how do I intervene?", run SDS extraction on the current ThoughtShape/MTSF object. Attach SDS signature as optional overlay with its own provenance.
5. **Later — Unified retrieval:** Query by shape tension (ThoughtShape), stencil (MTSF), or movement archetype (SDS) through one search API with three indexes over the same objects.

### 12.2 What Not to Do

- Do not replace MTSF with ThoughtShape as storage — MTSF is running and tested.
- Do not implement SDS as the primary extraction pipeline — it optimizes for motion, not phenomenological memory.
- Do not flatten ThoughtShape's Dimension × Station × Facet into MTSF flat qualities — extend the schema instead.
- Do not make lenses free-form prompts — ThoughtShape is correct that lenses are access modes, not chat templates.

## 13. Worked Example — Three Frameworks on One Input

**Input:** *"People do not get my product."*

### ThoughtShape reading

```text
Entity: Product (also: Founder)
Dimensions activated: User, Business, Founder, Brand, Product

User.Product comprehension = low
Founder.Psychological Recognition = unseen
Brand.Message clarity = abstract
Product.Onboarding value-reveal = slow

Cross-dimensional chain:
  founder feels unseen → overexplains → brand abstract → users confused
  → conversion drops → founder more unseen

Tensions: visibility vs comprehension, conviction vs communication
```

**Founder Lens output:** Story of seeing what others miss; pitch opening that names the hidden frustration.  
**Product Lens output:** Guided first-use flow that reveals value before explanation.

### SDS reading

```text
Entities: founder, user, product, market
Roles: signal_source, receiver, medium, environment
States: low user comprehension, high founder investment, abstract messaging
Feedback loop: low comprehension → founder explains more → message complexity ↑
              → comprehension ↓
Archetype: signal_dilution_through_accumulation (or education_burden)
Failure mode: CAC rises, activation stalls
Intervention: reduce signal layers, create single lead action, test comprehension
Anti-match: "maze" — no guaranteed path exists
```

### MTSF reading

```text
Entity: thought tube (hub), product, founder
Qualities: comprehension (low), visibility (paradoxical), clarity (low)
Relations: founder→product (carries conviction), product→user (fails to transmit)
Candidate shape: cand-metaphysical-actual-bridge
Stencil: field→landscape→probe→sink
Assertion store: 10 session evidence spans
```

### Synthesis

- **ThoughtShape** tells the product what to show in each lens and preserves the founder's felt unseen-ness.
- **SDS** tells the strategist what loop is running and what to break.
- **MTSF** tells the system what to remember and how to find this pattern again in six months.

## 15. Final Verdict

### 15.1 One-sentence definitions

| Framework | Definition |
|-----------|------------|
| **MTSF** | A modular kernel for capturing, storing, discovering, and actualizing thought-structure across metaphysical, latent, and actual spaces. |
| **SDS** | A hybrid architecture for extracting systems-in-motion and matching them across domains through validated movement signatures. |
| **ThoughtShape** | A multidimensional meaning grammar where lenses transform the same relational shape into product, story, risk, and strategy surfaces. |

### 15.2 How to use all three

| If you need… | Use… |
|--------------|------|
| Remember what the user thinks across sessions | **MTSF** |
| Represent a thought with faceted, dimensional precision | **ThoughtShape** |
| Route a thought through Founder/Product/Risk/Brand lenses | **ThoughtShape** |
| Find cross-domain analogies with anti-hallucination | **SDS** |
| Design interventions and break feedback loops | **SDS** |
| Discover unknown recurring patterns in corpus | **MTSF** |
| Produce artifacts from thought-structure | **MTSF** actualization + **ThoughtShape** expression routing |
| Hold ambiguity without over-structuring | **ThoughtShape** Hold + **MTSF** silence invariant |

### 15.3 Bottom line

The two-way conclusion (MTSF = substrate, SDS = reasoning layer) still holds. Adding ThoughtShape completes the stack:

```text
ThoughtShape  =  what meaning IS (ontology + lenses)
MTSF          =  what the system REMEMBERS (substrate + discovery)
SDS           =  what the system INFERS about MOTION (analogy + intervention)
```

For Thought Tube, **ThoughtShape is the product grammar**, **MTSF is the engine room**, and **SDS is the analogy/intervention specialist** invoked when the user needs to see their thought move — or see where it could move — in another domain.

## 17. ThoughtShape Report — Key Conclusions (Integrated)

The following conclusions from the ThoughtShape report are now part of this evaluation:

1. **Thought is not a sentence** — it is a relational configuration expressible through many surfaces.
2. **Thought is not flat** — entities exist across dimensions; stations project differently per dimension.
3. **Stations split into facets** — `Station × Dimension × Facet = StateClaim`.
4. **Facets become subsystems progressively** — not by default.
5. **Relations create shape** — especially cross-dimensional relations.
6. **Provenance is mandatory** — confirmed vs inferred vs hypothetical must be distinguished.
7. **Lenses are structured access modes** — not prompts; all operate on one ThoughtShape.
8. **Progressive depth** — Hold before Differentiate; expand only when the thought requires it.

These principles should guide Thought Tube product design and MTSF schema extensions, with SDS brought in when cross-domain motion and intervention are the user's intent.
